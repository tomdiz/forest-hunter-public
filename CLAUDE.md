# CLAUDE.md

Forest Hunter: a one-level isometric 3D game, built in Xogot (Godot 4.7) in GDScript. A personal learning project.
Read `docs/game-design.html` for the design. This file covers how to work in the project.

## Working with Xogot

- Drive the editor with the `xo` command, not by editing files. It is not on the PATH:
  `/Applications/Xogot.app/Contents/MacOS/xo`. Use `xo script create|patch` for scripts, `xo node ...` for scenes,
  `xo file send` to import assets, and `xo scene save` to save. The editor can hold unsaved changes, so editing
  `.tscn` or `.gd` files directly can be lost or overwritten.
- More than one Xogot window can be open. Run `xo list` and pass `--app <name>` (names change each launch;
  match on `projectPath`).
- Check a script after editing it: `xo script check <path>`. Read `diagnostics` in the reply.
- Test in the running game: `xo project run --scene res://scenes/level.tscn --wait`, then `xo game eval`,
  `xo game input action <name> --press|--release`, `xo game input mouse move --to X,Y`, and
  `xo editor screenshot <file> --source game`. Stop with `xo project stop`. Look at screenshots before saying
  something visual works.
- `xo eval` (editor GDScript): use a complete script (`@tool`, `extends EditorScript`, `func _run()`) when you need
  helper functions. Plain statements are wrapped in a function, so inner `func` definitions become lambdas.
  Indent with tabs, not spaces. Give loop variables types (`for s: float in [...]`) when you use `:=` on the result.
- `xo game eval` runs inside the game. It has `root` (the Window) but no `get_tree()`, so use `root.get_tree()`.
- Node paths in `xo` start at the scene root as `/`. Property values go through `str_to_var`:
  `'Vector3(0,1,5)'`, `'"text"'`, `'NodePath("../Player")'`.
- Exporting a `Node3D` and setting it with a `NodePath` stores a path where the script expects a node, and it
  ends up null. Export a `NodePath` and resolve it with `get_node_or_null`, as `camera_rig.gd` does.
- After patching a script with `@export` values, reload scenes that use it before saving
  (`xo scene reload --force`), then check the scene diff.
- Imported models: after a texture is added next to a model, run `xo file reimport` on the models, or they stay
  white. Instances of imported scenes need Editable Children (set it from `xo eval`) before you add nodes inside them.

## Code conventions

- GDScript, typed where it is easy. Tabs for indentation. Constants in `UPPER_SNAKE`, signals declared at the top.
- Input uses InputMap actions, not keys: `move_left`, `move_right`, `move_up`, `move_down`, `shoot`, `reload`.
- Groups connect parts of the game: `player`, `stag`, `hide_spots`. The HUD finds the player and stag by group.
- Damage is duck-typed: the rifle calls `take_damage(1)` on whatever its ray hits, if that has the method.
  The stag calls `take_hit()` on the player.
- Signals carry state to the HUD: the player emits `health_changed`, `ammo_changed`, `reloading_changed`, `died`.
  The stag emits `health_changed` and `died`.
- Physics and movement run in `_physics_process`. The camera is a child of `CameraRig`, which follows the player.
- Isometric input is turned by `CAMERA_YAW` (45°) so "up" means up the screen. Change both if the camera changes.
- Keep the tuning numbers as constants at the top of each script. The design page quotes them.

## Layout

- `scenes/level.tscn`: main scene. `actors/`: `player`, `camera_rig`, `stag`, and the animals `fox`, `deer`, `rabbit`.
  The animals share `scripts/critter.gd` (tuned with exports) and sit on collision layer 2, so the hunter walks through them
  but the rifle ray still hits them. The rabbit is a static model with `hops` on. `ui/hud.tscn`: HUD and end screens.
- The level's geometry sits under `World` (a `NavigationRegion3D`). The navigation mesh is baked from
  static colliders. Rebake it after you move or add colliders (see the bake recipe in the xogot-game-design skill).
- The level was generated by a script, so hand edits to it are normal from here on. There is no generator in the repo.

## Title screen

- `ui/title.tscn` (script `scripts/title.gd`) is the last child of the level. It builds its UI in code, locks the player
  (`player.locked`), hides the HUD and touch sticks, and offsets the camera (`CameraRig.offset`) so the hunter stands to
  one side. Enter, the Play button or a screen tap starts the game and glides the camera back.
- The `Game` autoload (`scripts/game.gd`) holds `title_seen`, so a restart (which reloads the scene) skips the title.

## Sound

- Volume: `Settings` (autoload, `scripts/settings.gd`) creates `Music` and `SFX` audio buses at startup and sets them
  from two 0 to 1 values, saved in `user://settings.cfg`. Route a new player to a bus with `player.bus = &"SFX"` or
  `&"Music"`. The options menu (`ui/options.tscn`, group `options_menu`) opens with Esc or the Options button.
  With mouse emulation off, its sliders and Done button are also driven from raw screen touches in `options.gd`.

- `scripts/sfx.gd` is an autoload (`Sfx`). `Sfx.play("name")` plays a flat sound (hunter, UI). Give a position,
  `Sfx.play("name", global_position)`, for a sound in the world that fades with distance. `Sfx.looped("name")` returns a
  looping copy for a caller's own player. Add a new sound by adding it to `SOUNDS` and dropping a WAV in `audio/`.
- The sounds are synthesised by `tools/gen_sounds.py` (`python3 tools/gen_sounds.py audio`), so there is no third-party
  audio and no license to track. The owner has listened and judged them good enough for a demo. Keep WAV import compression off
  (`compress/mode=0`): the default QOA compression breaks loop lengths.
- `scripts/music.gd` is the `Music` autoload: a calm loop and a tense loop play together and are crossfaded. `Music.start()`
  (called by `level.gd`), `Music.set_tension(bool)` (the stag, while it stalks or charges) and `Music.stop()` (the end
  screens). M toggles mute. The loops come from `tools/gen_music.py`; keep `compress/mode=0` on them too. `Music` loads its
  streams itself and does not use `Sfx`, because autoloads cannot rely on one another during `_ready`.
- `scripts/level.gd` starts the forest ambience and the campfire crackle, and puts the `AudioListener3D` on the hunter
  (the camera is far from him, so its own listener would make every positional sound faint).
- `Sfx` is `PROCESS_MODE_ALWAYS` so the win and lose stings still play while the game is paused.

## Look and lighting

- Kenney models import with `metallic = 1` (the glTF default), which renders black without reflections, and in a teal
  palette. `scripts/level.gd` (on the Level root) makes every such material under `World` matte and recolours the leaf,
  grass and wood materials by name (`COLORS`). Add new Kenney props under `World` and they get the same treatment.
- The sun sits at -58° pitch with 0.75 shadow opacity. Steeper and softer shadows keep the tall pines from throwing
  long black patches. The river is rough (0.5) so the campfire light does not glare on it.

## The level's ends

- The river has two extra water boxes, `World/River/Upstream` and `Downstream`, carrying the water about 34 m past each end
  wall so it never ends in a flat edge in view. They have no collision. Backdrop trees and plants under them were removed.
  Keep them out of any code that treats `River` children as the river's centre line (the map dump skips them by name).
- The hunter starts at (-35.4, 0, 16.4): the middle of the walkable band, about 4 m from the bank and the south wall, with
  at least 3.9 m of free room in every direction.

## The bridges

- `World/Bridge1` to `Bridge3` (west, middle and east of the level; Bridge3 is near the start) are plank footbridges (about 10.6 m long, 2.4 m wide, deck at 0.25 m with a ramp at each
  end). Each has a hole cut in `RiverBlock` (the neighbouring wall segments are shortened) and its own `Body` with rails
  and one `ConvexPolygonShape3D` for the deck and ramps. Use one convex shape: separate deck and ramp boxes made the
  stag's wide collision box catch on the seam.
- The side `Rail` colliders run the full 10.6 m, over the ramps as well as the flat deck. When they stopped at the deck, the
  0.25 m side lip of a ramp was a wall the hunter snagged on, yet the baked nav mesh counted it as walkable.
- The navigation mesh must be rebaked after any collider change, with `agent_radius` 0.5 (0.8 was too wide for the
  bridge). Both banks join only through the bridges, so the stag crosses them to reach hiding spots on the far side.

## The cabin

- Usable props: `scripts/cabin.gd` is on `World/Cabin`. Under `Interactions` are four `Area3D` nodes with
  `scripts/interactable.gd` (Door, Bed, Table, Fireplace). While the hunter stands in one, it registers with him
  (`add_interactable`); E fires the nearest one's `used` signal and the HUD shows its `prompt`. Add a new prop the same way.
  The door has a `DoorBlock` collider that only switches on while it is shut. Closing is refused if the hunter is in
  the doorway. The bed heals once (`player.heal`, `hud.blink`), the table gives 6 rounds once.
- The stag gives up a charge after `CHARGE_GIVE_UP` seconds, so it cannot stand outside a shut door forever.

- `World/Cabin` is built from cylinders (logs) and boxes, in groups: `Logs`, `Foundation`, `Roof`, `Chimney`,
  `DoorAndWindows`, `Porch`, `Interior`. Its local +Z faces the river. The footprint is 5 x 4 m.
- The collision (`Body`) is still the simple walls from the first version, with a gap at the door. The navigation mesh
  was baked from it, so if you change the footprint or add solid furniture, rebake the navigation mesh.

## The weapon

- The hunter's gun is chosen by `WEAPON` in `scripts/player.gd` (`"revolver"`, `"pistol"` or `"rifle"`). `_equip()` frees the
  Rifle node that is in the hunter scene, instances the chosen model under `RifleMount`, makes it `top_level`, and paints it.
  `_process` then turns it every frame so its barrel points along the facing direction, with the grip at the right wrist.
- Gun parts are painted by material name (`WEAPONS[...].colors`), which suits models that ship with plain white materials.
- Each spec's axes (`forward`, `up`) and points (`grip`, `muzzle`) are in the skeleton space of the SKINNED mesh. Do not
  take them from the raw vertex data: the skin rotates it (raw +Y was the rear of the rifle, and the pistol's long axis
  is X raw but Z skinned). Measure them by applying each bone's pose times the skin bind pose to the vertices, or put
  marker spheres on the mesh node and look. The rifle's axes are only approximate: it is tilted.
- Shots start at the weapon's `muzzle` point, so the tracer and flash come from the gun.

## Touch controls

- `ui/touch_controls.tscn` (script `scripts/touch_overlay.gd`) shows two floating sticks and a reload button when
  `DisplayServer.is_touchscreen_available()` is true, or when `always_show` is on. It presses the same InputMap
  actions as the keyboard and sets `player.touch_aim` and `player.touch_mode`. In touch mode the player ignores the mouse.
- `input_devices/pointing/emulate_mouse_from_touch` is off, so touches never turn into mouse clicks (a stick touch
  would otherwise fire the rifle). The end screen handles taps itself for that reason.
- No real iPhone testing yet. To test on the Mac, call `_set_active(true)` on the overlay with `xo game eval`, then send
  `InputEventScreenTouch` and `InputEventScreenDrag` events with `Input.parse_input_event` (they apply on the next frame).
